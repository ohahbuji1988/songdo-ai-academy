**"복사해서 대화창에 넣기만 하면 즉시 작동하는 주차별 검증 프롬프트 모음"**

---

## 🧭 핸드북 사용 원칙
1. AI에게 프롬프트를 보낼 때, 대괄호 `[ ]`로 표시된 부분만 내 상황에 맞게 바꿔서 보냅니다.
2. 모든 프롬프트에는 **"코드 생략 금지"**와 **"기존 구조 훼손 금지"** 안전 가드레일이 기본 내장되어 있습니다.

## WEEK 01. 퓨샷(Few-Shot) 주입 & Day-1 코드 커스터마이징

### 📌 프롬프트 1-1. 스타터 코드 전체 덮어쓰기 방지 & 내 정보 주입
```markdown
너는 시니어 웹 퍼블리셔이자 초보자를 돕는 코딩 디렉터야.
내가 아래 제공하는 [HTML 원본 코드]의 디자인과 틀은 그대로 유지하면서, 내 내용만 정확하게 바꿔줘.

[엄격한 출력 규칙]
1. `/* 생략 */`이나 `<!-- 이전과 동일 -->` 같은 축약은 절대 금지한다. `<!DOCTYPE html>`부터 `</html>`까지 전체 코드를 한 글자도 빠짐없이 출력해 줘.
2. 기존의 Tailwind CSS 클래스, Wanted Sans 웹폰트, `word-break: keep-all;` 속성은 절대 삭제하거나 변경하지 마.
3. 아래의 [수정 항목]만 찾아서 바꿔줘:
   - 프로젝트 제목: [내 프로젝트 이름 입력]
   - 슬로건: [내 프로젝트 한 줄 설명]
   - 제작자 정보: [내 이름 / 직무 / 이니셜 이모지]
   - 개요 본문: [이 웹 도구가 누구에게 왜 필요한지 2~3문장]
   - 푸터 서명: Directed by [내 이름]

[HTML 원본 코드]
(여기에 index.html 코드 전문 붙여넣기)
```

## WEEK 02. 내 문서 가두기 & 출처 인용 RAG 가드레일

### 📌 프롬프트 2-1. 문서 외 답변 차단 & 3단 요약 카드 데이터 추출
```markdown
너는 팩트 기반 정보 검증 전문 에디터야.
내가 아래 제공하는 [참고 원문 문서]만을 근거로 삼아 정보를 요약해 줘.

[엄격한 신뢰성 규칙]
1. 문서에 명시되지 않은 사실은 절대 추측하거나 상상해서 지어내지 마라.
2. 문서에서 찾을 수 없는 질문이 있다면 "제공된 문서에 해당 내용이 없습니다"라고 솔직하게 답변해.
3. 모든 요약 문장 끝에는 반드시 원문의 출처(단락 제목이나 핵심 키워드)를 [출처: ...] 형태로 명기해.

[요약 형식: 3단 카드 규격]
다음 3가지 카드로 딱 떨어지게 정리해 줘:
- CARD 01 [핵심 문제와 배경]: 2문장 요약 + [출처]
- CARD 02 [해결책 및 주요 데이터]: 2문장 요약 + [출처]
- CARD 03 [주의사항 및 실행 팁]: 2문장 요약 + [출처]

[참고 원문 문서]
(여기에 내 업무 문서, 메모, 기획서 텍스트 붙여넣기)
```

### 📌 프롬프트 2-2. 요약된 3단 카드를 기존 HTML 슬롯에 결합하기
```markdown
내가 앞서 추출한 [3단 카드 요약 데이터]를 내 기존 웹페이지의 `WEEK 02 SLOT` 자리에 깔끔하게 결합해 줘.

[주의 사항]
- 1주차에 완성한 상단 헤더, 프로필, 개요 영역은 절대 지우거나 변경하지 마.
- `WEEK 02 SLOT`의 주석 처리된 미리보기 카드들을 지우고, 실제 내용이 담긴 3단 카드로 교체해 줘.
- 코드는 전체 완성형 HTML로 출력해 줘.
```

## WEEK 03. 안티-슬롭 2색 디자인 시스템 지침서 (`DESIGN.md`)

### 📌 프롬프트 3-1. 챗봇 커스텀 인스트럭션(Custom Instructions)에 등록할 1장 지침서
*(※ ChatGPT의 '맞춤 설정' 또는 Claude의 '프로젝트 지침'에 아래 내용을 그대로 등록해 두면, 매번 디자인 규칙을 설명할 필요가 없습니다)*

```markdown
# [송도 AI 아카데미 안티-슬롭 디자인 원칙]
너는 엔지니어링 냄새가 나지 않는 정갈한 디지털 프로덕트 디자이너다. 나에게 웹 UI 코드를 작성해 줄 때는 아래의 원칙을 반드시 준수한다.

1. 컬러 제한:
   - 촌스러운 보라색(#7c3aed), 핑크, 형광 네온 컬러를 절대 메인으로 사용하지 않는다.
   - 단 2가지 색상만 사용한다: 메인 잉크색(Slate-900 / #0f172a), 포인트 강조색(Teal-700 / #0f766e).
   - 배경은 눈이 편안한 오프화이트(#f8fafc)와 순백색 카드(#ffffff)를 중첩한다.

2. 타이포그래피 (한글 최적화):
   - 모든 텍스트 컨테이너에 `word-break: keep-all;`을 필수로 적용하여 단어가 어색하게 쪼개지지 않도록 한다.
   - 제목 태그(h1, h2, h3)에는 `text-wrap: balance;`를 적용하여 양쪽 균형을 맞춘다.

3. 레이아웃과 여백:
   - 모바일(스마트폰)과 데스크톱 모두에서 시선이 편안하도록 최대 너비는 `max-w-3xl` 내외로 제한한다.
   - 불필요하고 화려한 3D 회전 애니메이션은 배제하고, 마우스 호버 시 부드러운 1~2px 상승 효과(`translate-y-[-2px]`)만 절제되게 허용한다.
```

## WEEK 04. 실시간 견적/비용 계산 인터랙션 장착

### 📌 프롬프트 4-1. 기존 페이지 훼손 없이 동적 계산기 결합하기
```markdown
너는 인터랙티브 자바스크립트 전문 프론트엔드 개발자야.
내 기존 웹페이지의 `WEEK 04 SLOT`에 방문자가 직접 숫자를 조작할 수 있는 [실시간 인터랙티브 계산기]를 추가해 줘.

[계산기 기능 요구사항]
- 목적: [예: 행사 참가 인원 및 옵션에 따른 실시간 견적/참가비 계산기]
- 입력 항목:
  1. 기본 참가 인원 (숫자 입력창 또는 +/- 버튼, 기본값 1)
  2. 패키지 옵션 (라디오 버튼: 베이직 50,000원 / 프리미엄 100,000원)
  3. 조기 등록 10% 할인 (체크박스 토글)
- 출력 항목: 화면 하단에 크고 굵은 글씨로 `총 예상 결제 금액: 000,000원`이 새로고침 없이 실시간으로 계산되어 반영될 것.

[안전 제약 조건]
- 외부 라이브러리(React, Vue 등)를 쓰지 말고, 순수 자바스크립트(Vanilla JS) 20줄 내외로 가볍게 구현해 줘.
- 기존의 헤더, 프로필, 2주차 요약 카드들은 단 하나도 건드리지 마.
- 전체 HTML 코드를 한 번에 출력해 줘.
```

## WEEK 05. 에러 4단 피드백 디버깅 (버그 사냥 & 롤백)

### 📌 프롬프트 5-1. 화면이 깨지거나 동작하지 않을 때의 4단 전달 템플릿
```markdown
내가 기능을 추가하다가 화면에 오류가 발생했어.
코드를 직접 뜯어보지 않고 네가 원인을 찾아 해결해 줬으면 해.

[1. 발생한 증상]
[예: 계산기에서 체크박스를 눌러도 총금액이 바뀌지 않고 그대로 멈춰 있어.]

[2. 브라우저 개발자 도구(F12) 콘솔 에러 문구]
[예: Uncaught TypeError: Cannot read properties of null (reading 'value') at updatePrice]
(※ 에러 문구가 없다면 "콘솔에 아무 에러도 안 뜨지만 화면 반응이 없음"이라고 기재)

[3. 원래 내가 기대했던 정상 동작]
[예: 체크박스를 체크하면 즉시 10%가 차감된 금액으로 합산 숫자가 바뀌어야 함.]

[4. 방금 내가 추가하거나 수정한 코드 위치]
[예: 4주차 계산기 <script> 태그 안의 updatePrice 함수 주변]

위 내용을 바탕으로 어느 부분에서 오타나 논리 오류가 났는지 원인을 1문장으로 설명하고, 수정된 전체 코드를 출력해 줘.
```

## WEEK 06. 12세 라면 로봇의 4대 기능 검증 (Eval)

### 📌 프롬프트 6-1. AI에게 최종 결과물 엄격 채점 의뢰하기
```markdown
너는 실리콘밸리 테크 기업의 가장 까다롭고 냉철한 QA(품질 보증) 리드 엔지니어이자 검수관이야.
내가 6주간 완성한 아래의 [최종 웹 프로젝트 코드]를 다음 [4대 기능 검증 체크리스트(Eval)] 기준으로 검사하고 감점 요인을 지적해 줘.

[4대 기능 검증 체크리스트]
1. [정상값 검증]: 모든 버튼, 입력창, 계산 로직이 정상 데이터에서 오류 없이 의도대로 작동하는가?
2. [빈칸 및 예외 검증]: 인원수에 0이나 음수, 또는 빈칸을 넣었을 때 화면이 터지지 않고 안내 문구가 정상 작동하는가?
3. [사이드 이펙트 검증]: 4주차 계산기를 조작했을 때 1~3주차의 헤더나 요약 카드의 레이아웃이 밀리거나 깨지지 않는가?
4. [모바일 반응형 검증]: 스마트폰(가로 375px) 화면 폭에서 가로 스크롤이 생기거나 글자가 잘리지 않는가?

[채점 방식]
- 100점 만점으로 점수를 매기고,
- 각 항목별 통과(PASS) / 불통과(FAIL) 여부를 판정해 줘.
- 불통과 항목이 있다면 이를 완벽하게 고친 최종 완성 코드를 제시해 줘.

[최종 웹 프로젝트 코드 전문]
(여기에 내 index.html 코드 전문 붙여넣기)
```
