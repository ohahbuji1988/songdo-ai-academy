**최종 평가는 84점, ‘소규모 시범 수업을 열 수 있는 수준’입니다.** 조기 배포와 실습 중심 구조는 확실히 좋아졌습니다. 다만 **근거 없는 상위 비율, AI 요약 비서의 작동 방식, 수업 시간·지원 체계**는 정식 모집 전에 수정해야 합니다.

1차 기획서와 검수 전문은 제공되지 않았으므로, **제시하신 74점과 지적 사항을 기준으로 한 재평가**입니다. 점수는 교육 설계에 대한 제 판단이며 실제 수료 성과를 측정한 결과는 아닙니다.

### 1. 1차 대비 개선도: 두 가지는 개선됐고, 한 가지는 미해결입니다

| 평가 항목 | 판정 | 검수 의견 |
|---|---|---|
| Day-1 조기 배포 | 크게 개선 | 첫날 결과물을 갖고 시작하는 것은 강점입니다. 다만 ‘30분’은 사전 준비가 끝난 경우의 목표로 제시해야 합니다. |
| 현실적 포지셔닝 | 미해결 | ‘상위 0.05%’를 ‘상위 20%’로 바꿔도 비교 대상과 조사 근거가 없으면 같은 문제입니다. |
| 단일 구독 완결성 | 조건부 개선 | 브라우저에서 계산·동작하는 웹 도구라면 가능합니다. 방문자에게 실시간 AI 답변을 제공하는 서비스까지 포함하면 별도 설계가 필요합니다. |
| 자립 역량 평가 | 개선 | 새 기능 추가→수정→재배포는 좋은 수료 시험입니다. 합격 기준을 더 구체화하면 됩니다. |

**가장 먼저 바꿀 것은 슬로건과 계층 구조입니다.**

‘대다수 80%’, ‘상위 20~30%’는 모집 문구의 신뢰도를 떨어뜨립니다. 특히 “과대광고 없는 솔직한 6주”라는 선언과 충돌합니다. 챗봇으로 질문하고 문서를 만드는 활동도 충분히 전문적일 수 있어, 이를 ‘단순 잡담 소비자’로 낮춰 부를 이유가 없습니다.

또한 제시된 **3단계와 비율을 카파시의 공식 분류라고 인정할 원문 근거가 확인되지 않았습니다.** 출처를 제시할 수 없다면 ‘본 아카데미의 학습 단계’로 명시하세요. 연구원과 웹 도구 제작자는 서로 다른 전문 분야이므로 하나의 사다리로 줄 세우는 것도 부정확합니다.

추천 슬로건은 다음과 같습니다.

> **AI와 대화하던 사람에서, 내 웹 도구를 만들고 고치는 사람으로. 6주 동안 제작·검증·배포까지.**

### 2. 나선형 학습: 작동할 수 있지만, ‘덧붙이기’만으로는 부족합니다

**하나의 작은 프로젝트를 반복해서 개선하는 방식은 비전공자에게 적합하다는 판단입니다.** 매주 새 도구를 배우는 부담을 줄이고, 지난주에 만든 결과와 이번 주의 변화를 비교하기 쉽습니다.

다만 지금 구성은 일부가 ‘소개 페이지에 서로 다른 기능을 붙이는 과정’에 가깝습니다. 나선형 학습은 같은 핵심 행동을 조금씩 어려운 조건에서 반복하는 구조여야 합니다.

매주 다음 순서를 고정하는 편이 좋습니다.

> **필요 정하기 → 작은 변경 요청 → 결과 확인 → 기존 기능 재확인 → 재배포**

이를 위해 세 가지를 조정하세요.

- **디버깅과 검증을 1주차부터 시작하세요.** 5주차는 첫 디버깅 시간이 아니라, 일부러 심어둔 오류를 스스로 찾는 심화 시간이어야 합니다.
- **프로젝트의 사용 목적을 하나로 묶으세요.** 예를 들어 ‘행사 안내 페이지→준비물 카드→참가비 계산기’는 연결됩니다. 소개 페이지에 요약 비서·룰렛·투표기를 모두 붙이면 기능은 늘어도 제품의 목적은 흐려집니다.
- **실제 사용자 테스트를 4주차로 당기세요.** 6주차에 처음 문제를 발견하면 수정할 시간이 없습니다. 6주차에는 개선 결과를 다시 확인하세요.

수업 시간도 반드시 명시해야 합니다. **시범 운영안으로 주당 수업 3시간과 자율 실습 2시간 정도**를 제안합니다. 이는 검증된 최소 시간이 아니라 출발점이며, 초보자 시범 수업으로 조정해야 합니다.

### 3. 런칭 전 반드시 해결할 맹점

**① ‘AI로 만든 웹 도구’와 ‘AI가 작동하는 웹 서비스’를 구분해야 합니다.**

현재 가장 큰 혼동은 2주차의 ‘정보 요약 비서’입니다.

- 수강생이 AI로 문서를 요약한 뒤, 확인한 내용을 카드로 게시한다면 현재 원칙과 맞습니다.
- 방문자가 문서를 넣을 때마다 웹사이트가 새로 요약한다면, 요약을 수행할 모델과 실행 환경이 추가로 필요합니다.

**유료 구독 하나가 공개 웹사이트 방문자의 AI 사용까지 대신 결제해 주는 것은 아닙니다.** 따라서 산출물 이름을 다음처럼 고치는 것이 안전합니다.

> **내 문서를 AI로 요약하고 원문과 대조해 게시한, 출처 포함 정보 카드**

문서를 대화창에 넣는 것과 RAG도 구별하세요. RAG는 **문서 더미에서 관련 부분을 찾아 AI에게 건네는 방식**입니다. 직접 구현하지 않는다면 ‘문서 기반 답변과 RAG 개념 맛보기’가 정확합니다.

**② ‘0원’은 설계 조건으로 약속해야 합니다.**

추천 문구는 다음과 같습니다.

> **기존 유료 AI 구독 외 추가 API 비용 없이, 지정한 무료 호스팅의 제공 범위 안에서 제작합니다.**

구독에는 사용량 제한이 있고, 무료 호스팅에도 한도가 있습니다. 예를 들어 Claude 유료 플랜은 사용량 제한을 적용하며, Netlify 무료 플랜도 월별 크레딧을 제공합니다. 따라서 사용량 소진 시 진행할 **원문 검증·사용성 점검 같은 대체 실습**이 필요합니다. [Claude 공식 요금 안내](https://claude.com/pricing), [Netlify 무료 플랜 안내](https://www.netlify.com/pricing/personal-vs-free/)

ChatGPT와 Claude를 모두 허용하더라도 **수업의 기본 경로는 하나로 정하고**, 다른 구독자를 위한 별도 안내서를 준비하세요. 학습 목표가 같아도 화면과 파일 처리 방식까지 같지는 않습니다.

**③ Day-1 30분은 ‘준비 완료 후’ 기준으로 운영하세요.**

개강 전에 계정 로그인, 파일 저장·압축 해제, 호스팅 접속을 확인하세요. 첫 페이지는 **미리 준비한 기본 파일에서 이름·소개·색상을 바꾸는 수준**으로 제한하는 것이 좋습니다.

30분을 넘긴 수강생을 실패자로 만들지 말고, 수업 안에는 복구 시간을 확보해야 합니다. 배포 성공은 AI 미리보기 화면이 아니라 **다른 기기에서 공개 주소를 열어 확인한 상태**로 정의하세요.

**④ 자동화에 대한 과한 표현을 줄이세요.**

‘모름 지침 강제’와 ‘출처 인용 필수’만으로 오류가 사라지지는 않습니다. AI는 출처도 틀리게 제시할 수 있습니다. **출처가 적혀 있는지보다 원문에 실제로 그 내용이 있는지**를 평가해야 합니다.

‘스킬은 코드가 아닌 업무 지침서’도 입문 비유로는 좋지만, 실제 스킬에는 코드나 참고 파일이 포함될 수 있습니다. “이번 수업에서는 글로 된 업무 지침부터 만든다”가 정확합니다.

**⑤ 디자인 취향을 품질 기준으로 삼지 마세요.**

보라색 배제나 2색 팔레트는 연습용 제약으로는 괜찮지만 좋은 디자인의 보편적 기준은 아닙니다. 우선순위는 **읽기 쉬움, 휴대폰 화면, 버튼 구분, 키보드 조작, 적절한 움직임**입니다.

‘쫀득한 인터랙션’보다 ‘눌렸는지 알 수 있는 버튼’이 먼저입니다.

**⑥ 공개 범위와 복구 방법을 가르쳐야 합니다.**

첫날부터 실명·연락처·회사 내부 문서를 무심코 공개하지 않도록 가상 자료를 기본값으로 쓰세요. 매주 수정 전 정상 파일을 보관하고, 문제가 생기면 이전 상태로 되돌리는 연습도 포함해야 합니다.

투표기는 특히 범위를 명시하세요. **내 브라우저에만 저장되는 시연용 투표**와 **여러 사람의 표를 함께 모으는 투표 서비스**는 난도가 다릅니다.

### 4. 수료 기준과 최종 점수

‘12세 라면 로봇’은 수업용 비유로 남기되, 모집 안내에는 **기능 검증 체크리스트**라는 이름을 권합니다. 학생에게 무엇을 증명해야 하는지 더 명확합니다.

수료 시험은 다음 네 조건으로 정리하면 좋습니다.

1. AI 사용은 허용하고, 강사의 단계별 해결 지시 없이 작은 기능을 추가한다.
2. 정상 입력·빈 입력·잘못된 입력에서 결과를 확인한다.
3. 기존 기능이 여전히 작동하는지 확인한다.
4. 재배포하고, 문제가 생겼을 때 이전 상태로 복구할 수 있다.
